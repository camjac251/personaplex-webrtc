# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

PersonaPlex served over WebRTC on any CUDA GPU host with a public IP, defaulting to Kyutai's interactivity-aligned RL checkpoint with an NVIDIA-base rollback, optional vision, and snapshot/rewind safety. Single-session by design. WebRTC connects peers directly over UDP with no TURN relay.

## Key files

- `moshi/moshi/server.py` - server lifecycle (`ServerState`), HTTP/WebRTC routes, vision inject state machine, resume grants; serves the built dashboard from `moshi/moshi/web_client` (plain-text 503 when unbuilt).
- `moshi/moshi/rtc_session.py` - WebRTC peer connection, DataChannel protocol, `SessionConfig` (parse + clamp).
- `moshi/moshi/models/lm.py` - `LMGen` (sampling, anti-collapse, voice prompt loading). Voice prompt clips are boundary-silence-trimmed (100 ms guard) before LUFS normalization and tail slicing.
- `moshi/moshi/models/lm_controls.py` - typed sampling, volatile control, and preview state. Use `LMGen.apply_sampling`, speech/interrupt/reset methods, and preview capture/restore rather than private flag writes; sampling tensors retain their storage.
- `moshi/moshi/context.py` - bounded packet ownership, priority, camera generations, and cancellation. Camera transitions invalidate only vision-origin packets; typed notes and persona/seal/hold state survive.
- `moshi/moshi/recovery.py` - atomic LM/Mimi/RNG validation and in-place restore. Callers provide an explicit `RestoreIntent`; the server applies reset/retuning policy separately.
- `moshi/moshi/rtc_opus.py` - PyAV mono Opus encoder patched over aiortc's stock stereo encoder at import; falls back to the stock encoder if libopus/PyAV setup fails.
- `moshi/moshi/modules/streaming.py` - state flatten/restore used by snapshot/rewind.
- `frontend/src/App.jsx` - the React dashboard: realtime state machine, tuning console, signal strip, vision panel. `frontend/src/components/Transcript.jsx` renders turns with stick-to-bottom auto-follow (48 px threshold) and a Jump to live pill; `utils/transcript.js` parses vocal-event chips and `[vision]` echoes. `components/DirectorNotes.jsx` is the docked Direct/Inject composer. `frontend/src/data/dashboardData.jsx` holds slider defs and tooltips.
- `frontend/src/utils/sessionTrace.js` - bounded privacy-safe browser bug reports. It must never export audio/images, network or session identifiers, device IDs, credentials, or raw prompts/transcripts by default.
- `moshi/tests/duplex_harness.py` and `scripts/run_duplex_regression.py` - shared scenario validation/scoring and the real aiortc regression client.

## Architecture invariants

- `ServerState.lock` (asyncio.Lock) gates the single live session. Second connect returns HTTP 409.
- `ServerState._infer_lock` (threading.Lock) guards `lm_gen` state. Event-loop mutations dispatch to `ServerState._infer_executor` first; never sync-acquire from a coroutine.
- All model work, including startup warmup, stays on the one persistent `_infer_executor` worker. Arbitrary default-pool CUDA workers pay multi-second cold-context costs; inline GPU work starves aiortc keepalives.
- Startup uses cuDNN heuristic selection (`benchmark=False`) rather than repeated autotuning. Keep the eight warmup frames and compiled kernels; this lowers startup time/workspace but can change numerical codec decisions and seeded audio versus the old autotuned path.
- Vision inject drips one token per outer frame, only when `_vision_pad_streak >= LIVE_PROMPT_BOUNDARY_STREAK` and never within `POST_USER_TURN_INJECT_HOLDOFF_FRAMES` (~2 s) of a completed user turn, so a caption cannot displace reply formation. Outbound PCM zeroed during inject (with a ~10 ms boundary fade via `_gate_outbound_pcm`). Cap at `LIVE_PROMPT_MAX_STEPS`. An interrupted or capped drip window seals with one `_context_seal_token` (".") so no half-sentence dangles in the model's history. A persona-reinforcement drip interrupted mid-clause defers its seal to the first quiet frame, even inside the post-user-turn holdoff, so reply formation starts with a closed clause.
- Context drips replicate the t=0 conditioning ritual: forced text over forced-silent agent audio with the user channel swapped to `_encode_sine_frame()` (the 440 Hz sine every trained text prompt rode on), never on stop-latch or abort frames where the model must keep hearing the room. A fully delivered packet is followed by `CONTEXT_SEAL_HOLD_FRAMES` (~0.5 s) of forced PAD under the same ritual, mirroring the t=0 post-prompt silence slots, so the sentence files as a completed thought; user speech abandons the hold. Captions are phrased as second-person scenario context ("You are talking with ...") because that is the only text-conditioning distribution PersonaPlex trained on.
- Caption-CFG (`--caption-cfg` / `PERSONAPLEX_CAPTION_CFG=1`) runs two streaming rows for the process lifetime: row 0 conditions on injected context, row 1 receives PAD in those windows, text logits are guided as `uncond + cfg_gamma * (cond - uncond)`, one sample feeds both rows, and row 0's depformer codes overwrite row 1's audio slot so the KV timelines differ only by context text. The batch size is captured into the CUDA graphs at startup warmup and can never change live; Mimi stays single-row and only `tokens[0:1]` is ever decoded. `cfg_gamma` boosts to the session's `caption_cfg_gamma` when a packet completes and decays back to `LMGen.cfg_gamma_floor` (~2.5 s half-life). Persona-CFG (`persona_cfg_gamma` > 1.0 in the session config, default 1.5, connect-time only) extends the split to the t=0 text prompt: `LMGen.persona_cfg` makes row 1 receive PAD in every text-prompt frame (`_prompt_text_token`), the floor becomes the persona strength, and a caption boost is `max(caption_cfg_gamma, floor)`. The voice prompt and both silence holds still prime both rows identically. At 1.0 the rows prime alike and nothing changes. Roughly doubles per-frame transformer compute and adds ~1.6 GB of permanent streaming KV. Single-row voice sidecars restore into both rows: ordinary state tensors broadcast dim 0 through the validated `Tensor.copy_`, and `[2, 1, H, T, D]` KV caches are expanded along their batch axis first; legacy embedding replay expands to both rows. Rewind/restore resets `cfg_gamma` to the floor because the restored KV predates the boosting caption but carries the t=0 row split. `caption_cfg_gamma` is live-tunable; a live change applies to the next completed packet's boost, never the currently decaying value.
- Auto-rewind: runaway-text trips (`controls.pad_force_remaining` armed with reason `"dense"`) `COLLAPSE_TRIGGER_THRESHOLD` times in `COLLAPSE_WINDOW_SEC` restore the latest snapshot via `set_streaming_state_inplace` and reset sampling/anti-collapse controls to the active model's safe defaults while preserving configured PAD and onset biases. Manual/bookmark rewind preserves tuning. Restore preflights LM, Mimi, and CPU/CUDA RNG as one logical point before applying either module; always pass `dict(state_dict)` because apply consumes keys. Baselines and named bookmarks are pageable-CPU snapshots admitted against a 24 GiB host budget and 4 GiB available-memory floor by default. Their capture is two-phase: `_stage_snapshot` runs on the inference worker under `_infer_lock`, copies the LM tensors asynchronously into a pinned staging pool sized once at startup (`_snapshot_staging`, one LM state's worth of locked host RAM) and records a CUDA event; `_finish_snapshot` runs on `_snapshot_executor`, waits on that event, clones the pinned buffers into pageable memory, runs the free-floor check, and releases the staging lock. Stream order protects the live tensors, so the frame loop is delayed by the copy-engine time rather than blocked for a synchronous pageable transfer. Mimi's small, shape-varying conv states copy directly. A CPU capture that arrives while the pool is still draining is deferred, never queued. Callers use `_capture_snapshot`; `_take_snapshot` (stage plus finish on one thread) is for the periodic GPU capture and tests. Periodic recovery, when explicitly enabled, retains only the newest GPU snapshot under a 6 GiB budget and 2 GiB VRAM floor. Capture failure is nonfatal and cannot publish a partial bookmark. The measured Caption-CFG state is 3,162,118,280 bytes (2.945 GiB), not 1.6 GB. Auto-rewind accepts snapshots younger than `AUTO_REWIND_SNAPSHOT_MAX_AGE_SEC` (90 s), so with periodic snapshots off it goes inert after the baseline ages out; a trip that finds no usable snapshot still emits a warn `collapse` event (`triggers`, `window_sec`, `reason` `no_snapshot`/`stale_snapshot`, `snapshot_age_sec`) so the detection is visible even when recovery is unavailable. Snapshot capture defers while a context drip is active.
- Audio top-k is a scalar CUDA tensor consumed by a fixed-cardinality masked sampler, and audio temperature is a per-level `[dep_q]` CUDA tensor: levels 1-7 take `audio_temperature`, level 0 (the semantic codebook) takes `semantic_temperature_cap` as its own independent temperature (default 0.7 via `PERSONAPLEX_SEMANTIC_TEMP_CAP`; the name is historical, it is no longer a ceiling, so level 0 may run above or below the acoustic levels; upstream samples every level at 0.8). Live tuning must never reset or recapture the depformer CUDA graph. Text sampling supports optional min-p truncation (`text_min_p`, default 0 = off).
- Depformer early exit (`--depformer-early-exit` / `PERSONAPLEX_DEPFORMER_EARLY_EXIT`) is an experiment and defaults off. Values 8-16 skip trailing codebooks whose user-stream values are already supplied while consuming the stock sampler's RNG progression. It must stay off until the declared GPU and quality gates confirm graph/runtime parity.
- Attention sink (`--kv-sink-frames` / `PERSONAPLEX_KV_SINK_FRAMES`, default 0 = off): reserves the first N slots of the main temporal transformer's `RingKVCache` as never-evicted anchors and exempts positions `[0, N)` from the sliding-window mask, so the t=0 conditioning stays attendable past the 3000-frame context on long sessions. Keys are cached with RoPE applied. Anchor keys are written at their true rotation into both the cache and a pristine `sink_keys` buffer; once the ring has evicted frames, every step rewrites the cache's anchor slots from that buffer with the rotary phase advanced by the eviction count (`shift_rope`), so the query sees each anchor at its within-cache position (StreamingLLM numbering) and the query-to-anchor distance never exceeds the trained window. The shift is recomputed from the pristine copy each step rather than accumulated in bf16; that re-rotation touches every anchor of every layer on every live frame, so `shift_rope` is compiled and single-frame steps update only their own pristine slot (the eager version cost ~25 ms per frame at a 1,147-frame sink, past the 80 ms budget). Only the main transformer's cache is touched (the depformer runs `context=None` and never receives a sink). N is a construction-time int fixed before CUDA-graph capture (`RingKVCache.sink`), never streaming state. With N=0, or without RoPE, `asdict()` stays `{cache, end_offset}` and every `torch.where` collapses to the original ring expression (byte-identical); with N>0 and RoPE it adds `sink_keys`, so sink snapshots are not interchangeable with stock ones. `RingKVCache` raises when `sink >= capacity`. Behavioral quality (does it reduce drift) needs the `long_session_soak` A/B on a running server and is not yet measured.
- The default checkpoint is `kyutai/personaplex-rl-seamless` at its pinned revision; `PERSONAPLEX_MODEL=base` selects the pinned NVIDIA rollback and `PERSONAPLEX_MODEL=characterplex` the pinned `utkarshUY/CharacterPlex-FullFT-v4`. Repository and revision are one startup-time identity and voice markers include both. A repo without `voices.tgz` (CharacterPlex) takes its presets from the pinned NVIDIA base revision (`loaders.download_voice_archive`).
- CharacterPlex pinned memory: a `memory.json` in the checkpoint (or `PERSONAPLEX_MEMORY_JSON` for local weights) sets `LMGen.notes_frames` (64) for the process lifetime and raises the attention sink before the model is built to `MEMORY_VOICE_FRAMES` (70) + 2 x silence + `card_max_tokens` + `notes_frames` + 1 (1,147 for CharacterPlex), so any accepted card keeps NOTES pinned; `process_flags.kv_sink_frames` reports the effective value. Priming order is voice, silence, card (the text prompt), silence, NOTES slot, plus one PAD flush frame so the slot's last position is materialized. Slot text is the notes tokens then PAD (at most `notes_frames - 1` tokens, no `<system>` tags); caption-CFG row 1 always gets PAD there. `LMGen.rewrite_notes` replaces only the slot's main-transformer KV: it rewinds every transformer streaming offset to `notes_start`, runs one eager (non-graphed) forward over the slot, and restores the offsets in place, so frames after the rewrite see the new notes while earlier conversation KV is untouched. It is legal only while the whole prefix sits in its original slots: the slot ends inside the sink, or the ring has never wrapped; otherwise it raises `NotesUnavailable("evicted")`, because a rewound rewrite would attend to wrapped conversation frames as if they were the card. Rewrites run on `_infer_executor` under `_infer_lock`; the server keeps the latest notes and re-applies them after every restore/rewind and voice preview. The layout is reconstructed from the public release, not the authors' private runtime.
- Batched prefill (`PERSONAPLEX_BATCHED_PREFILL=1`, default off): `LMGen.prefill_system_prompts` replays `prepare_step_input`'s token-cache writes for every forced prompt frame and runs one eager transformer forward, leaving LM and transformer streaming state equal to the per-frame path; no depformer runs, so RNG consumption differs. Full-state voice sidecars are restored first; stored `.pt` voice embeddings replay `step_embeddings`' token-cache bookkeeping per frame, restore `voice_prompt_cache`, and join the same forward (1-row embeddings expand to both caption-CFG rows); sidecar creation keeps the per-frame path. A span that would reach the KV capacity falls back to per-frame steps. GPU parity (RTX A6000, caption-CFG, 344-frame prefix): next-token text KL ~0, top-5 identical, 0.37 s versus 16 s.
- Native-duplex defaults: `audio_temperature=0.8`, `padding_bonus=0.0`, `turn_onset_bias=0.0`, `repetition_penalty=1.0`, `max_turn_text_tokens=240`. `padding_bonus` is a signed mid-turn PAD logit bias clamped to [-1, 2] (`controls.non_pad_streak > 0`, with a forced-text hold so a caption drip never re-arms it at reply onset): positive paces words apart, negative suppresses mid-turn pauses; onset pacing belongs to `turn_onset_bias`, a live-tunable EPAD logit bias clamped to [-4, 4] that auto-rewind preserves. User configuration cannot lower max-turn below 40. Max-turn is a reply-length cap only: it counts natural text across brief PAD gaps, resets after `REPETITION_TURN_BREAK_FRAMES` natural PAD/EPAD frames, and its trips (`controls.pad_force_reason == "cap"`) never feed collapse detection. Loop detection is the runaway-text detector: `DENSE_TEXT_COLLAPSE_FRAMES` (40) consecutive natural non-PAD frames, a token every frame for 3.2 s, which speech never sustains; it arms the same forced-PAD window with reason `"dense"`, runs even when the cap is 0, ignores forced frames, and is the only trip auto-rewind counts. Native mode never turns client-detected overlap into an automatic interrupt; Assisted mode does. The repetition ring uses the same natural turn boundary. Turn-cap accounting reads the text token through an async pinned D2H copy gated by a CUDA event; the hot path never blocks on a per-frame `.item()`.
- Live turn handling includes `gentle`: server-only yielding after 15 voiced overlapping frames (~1.2 s), bridging at most two quiet frames without counting them. Unlike Assisted, activity-detector hangover is not evidence. Mode changes reset overlap accounting on the inference executor. Native is the default for RL and CharacterPlex (the dashboard also starts CharacterPlex at `turn_onset_bias` +1.0); the browser sends automatic interrupts only in Assisted. `floor` (optional) is server-only: while the user holds the floor the assistant may emit at most `FLOOR_BACKCHANNEL_TOKENS` (3) consecutive natural text tokens; beyond that, or after `FLOOR_BARGE_OVERLAP_FRAMES` (6) voiced frames over a reply already in progress, the server yields and forces PAD until the user's turn ends. Floor holds never clear queued context, never feed collapse detection, block automatic recovery capture, and emit `floor` hold/release events.
- Sentence-aware reply targets refine max-turn accounting: startup calls `LMGen.set_sentence_end_tokens()` with punctuation-ending tokenizer IDs. At the target, finish at the next terminal token or force the cap at target + `TURN_CAP_SENTENCE_GRACE_TOKENS` (24). Tokenizers without configured terminals retain the hard cap. Punctuation is approximate; dense-collapse precedence, forced-text exclusions, and expressive pacing remain unchanged.
- Automatic recovery selects only snapshots marked `auto_recovery_eligible` at capture, newest eligible first, then a still-fresh eligible baseline. The 90 s age ceiling remains. Periodic capture defers during user speech, Stop, forced yielding, pending auto-rewind, or the 8 s quarantine after a dense-text trip, in addition to the existing context/quiet gates. Manual bookmarks remain possible during Stop but are not eligible for automatic recovery. No extra GPU history is retained; ineligible recent points report `ineligible_snapshot`.
- Stop is latched: `_stop_response_latched` forces assistant PAD and zero PCM until the next valid user turn completes. A fixed one-second gate alone is insufficient because the model can resume the abandoned answer. `STOP_LATCH_MAX_HOLD_SEC` (12 s) force-releases a latch whose release detectors starve in sustained room noise. Every release emits one `stop_latch` event (`reason` `user_turn`, `hold_ceiling`, or `speak`, numeric `held_sec`) so the dashboard timeline shows which trigger freed the model. Rewind/new-session reset the latch; transport resume preserves it.
- A `speak` control requests one EPAD onset without resetting LM/Mimi state, voice, or RNG. It can release Stop, rejects active speech or context delivery, and leaves audio ungated. The cue defers through forced-text/cap frames and is cancelled by Stop, reset/rewind, or inbound speech.
- The slow `stat` envelope exposes cumulative inbound queue and outbound-buffer pressure; runtime summaries add bounded numeric snapshot bytes, timing, failure/rejection counts, and residency inventory. Keep those fields numeric and explicitly allowlisted; never put PCM, paths, SDP/candidates, or free-form secrets in telemetry.
- A `context_note` is experimental silent conditioning, not a private memory or user-message channel. Normalize whitespace and strip the startup-only `<system>` wrapper; reject rather than truncate notes over 180 characters or 32 tokens. Waiting manual packets cannot be replaced. The dashboard clears only an untouched, acknowledged draft and preserves drafts on rejection, concurrent edits, send failure, or disconnect. The model can still repeat note content aloud.
- The `stat` envelope carries `opus_encode_failures`, a process-wide count of dropped-frame encode failures from the mono Opus patch, plus the shadow counters `text_starved_frames`/`text_starved_episodes` (sustained natural PAD/EPAD text over non-silent output; observability only, never a control input).
- Vision captions are safe/UI-only by default. After-speech and on-demand injection are retired because GPU traces proved they are neither reliable next-reply grounding nor a private context channel. Unsafe Ambient react remains explicit, injects at most once per 8 s, and may speak without a user prompt. Gemini 3.8 Flash uses stateless requests (`store=false`), low thinking, and generation budgets of 1024 live/2048 detail tokens, including thinking. Valid caption JSON is accepted even from incomplete interactions. The response schema must not contradict the selected caption/detail prompt.
- Scene notes (`vision_notes`, SessionConfig and live `update_config`; only with `notes_frames > 0`): each new non-historical caption for the active camera generation is composed after the director notes into the NOTES slot via `rewrite_notes` on `_infer_executor` under `_infer_lock`. Director text has priority; the scene is trimmed by whole words to `notes_frames - 1` tokens and skipped if nothing fits. Unchanged scenes are skipped, caption rewrites are limited to one per `VISION_NOTES_MIN_INTERVAL_SEC` (4 s), and `set_notes` plus restore re-application keep the current scene. Camera stop, a generation change, or turning the flag off clears the scene. `NotesUnavailable("evicted")` latches scene notes off for the session with one warn event. `vision_notes` events carry only status, token count, and reason, never caption or note text. The dashboard never sends `vision_notes` and `vision_feed_model` both true.
- `torch.cuda.empty_cache()` in `_run_rtc_session.finally`. Model weights and KV cache buffer stay resident across sessions.
- Transport recovery is fresh-pc resume, not ICE restart (aiortc can't restart a live transport): unexpected transport death records a 25 s `_resume_grant`; a new offer with `resume_session_id` skips reset/warmup and continues from resident state; if that offer's `text_prompt` differs from the primed one the server logs a warning and emits a warn `resume` event (lengths only) but still does not re-prime. The dashboard's fresh Start retries a 409 `session_busy` answer a few times (`START_BUSY_MAX_ATTEMPTS`) because End-then-Start can race teardown. Server-initiated ends (`send_end`) and client `goodbye` must NOT record a grant; `goodbye` is flagged at receive time, before the serialized control queue, so a teardown that cancels the queued handler still suppresses the grant.
- WebRTC connectivity is direct: `handle_ice_servers` serves an empty `iceServers` list by default and aiortc advertises its own host candidate, so the server must run where that candidate carries the public IP (on the host, or a container with host networking). `WEBRTC_STUN_URLS` (comma-separated) is an optional escape hatch for NAT'd hosts; there is no TURN relay.
- Oversized vision frames travel as `vision_frame_chunk` sequences (48 KB chunks under the 64 KB SCTP message cap) reassembled server-side into the normal `vision_frame` path.
- Outbound audio stays float from Mimi through the 24->48 k resampler, passes a soft limiter (knee at 0.97), and quantizes to s16 exactly once at frame emit. An outbound underrun is a due playout frame the buffer cannot fill; an exact drain-to-zero on the 80 ms Mimi lump cadence is healthy and never fades or raises the prebuffer floor.

## Gotchas

- `LMGen.text_prompt_tokens` is startup-only. Mid-stream context goes in `_context.notes.waiting.tokens`.
- `LMGen.step` returns the text slot from `max_delay` steps back (1 with the shipped delays), so the token in `tokens[0, 0, 0]` was decided by the previous step. `_process_audio_frame` queues each step's `(forced, interrupt_gated)` pair in `_pending_text_flags` and attributes the emitted token to the dequeued pair; the transcript filter, pad streak, and starved-text telemetry use those flags. The outbound audio gate keys on the current step instead so the first gated frame cuts the natural audio still in the pipeline. Frame-loop test doubles must return the previous step's token.
- Mid-stream text injection is off-distribution. Boundary-streak + audio-gate + drip-feed is empirical; burst inject causes degenerate single-token loops.
- `<system>` wrap is t=0 only. Strip from mid-stream injected text.
- `set_streaming_state_inplace` pops the dict it's given. Pass a shallow copy.
- Streaming restore validates the full schema (dtype plus exact shape, or 1-row to N-row dim-0 broadcast only) before mutating any tensor; a failed restore leaves live state untouched.
- Aiortc `DataChannel.send` is not thread-safe. Schedule cross-thread sends via `loop.call_soon_threadsafe`.
